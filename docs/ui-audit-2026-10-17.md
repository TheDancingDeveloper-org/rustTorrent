# rustTorrent web UI audit — 2026-10-17

Phase 1 of 3 (audit → fixes → verification). Read-only: no source changes.

## Scope and method

- **Surface:** the React/Tailwind web UI in `crates/librtbit/webui/src/` (Operate mode: the user is completing a task).
- **Desktop shell:** `desktop/` is a Tauri wrapper. `desktop/src/index.html` is a splash screen that polls the local engine and then redirects to the same web UI, so the web UI findings cover the desktop app too. The splash is audited separately (findings P2-21 to P2-23).
- **Runtime:** a local Vite dev server on loopback, using the bundled mock API (`mock.html` → `src/main-mock.tsx` / `src/mock-api.ts`). No live or deployed instance was contacted. The "no daemon" captures load the real entry (`/`) with no backend behind it.
- **Captures:** Playwright Chromium at 1440×900 and 390×844 (mobile emulation with touch), in both light and dark (`prefers-color-scheme`; the UI follows the OS scheme and also has a toggle). They are under [`design/audits/2026-10-17/`](../design/audits/2026-10-17/) and named `NN-view-viewport-scheme.png`.
- **Detector:** `impeccable detect --json crates/librtbit/webui/src` returned `[]` (no mechanical hits). Every finding below comes from reading the code or the screenshots and was checked against both.
- **DOM probes:** on the main torrents view there are 8 buttons with no text and no `aria-label`. There are 53 interactive targets smaller than 44 px at 1440 px, and 31 at 390 px. No viewport scrolls horizontally at page level.

Paths below are relative to `crates/librtbit/webui/src/` unless they start with `desktop/` or `design/`.

## Implementation integrity verdict

**Partial pass.** The skeleton is coherent and specific to the product. `globals.css` has semantic tokens with a full `.dark` override. The compact table, status/category/tracker sidebar, detail pane and footer stats form a recognisable torrent-client workspace. Drift sits at the edges: three independent button systems, about 19 copy-pasted input class strings, a blue accent (`text-blue-500`) fighting the orange `--color-primary`, and feature pages (RSS, Indexarr, logs) that skip the tokens. None of this is structural. Most of it can be fixed one file at a time.

## Executive summary

## Findings

### P0 — Blocking

**P0-1. Page navigation disappears below `lg`, so RSS and Index can't be reached on mobile or tablet**
- **Location:** `components/Toolbar.tsx:236` (`{isLargeScreen && (` wraps the Torrents/Index/RSS tabs at lines 237–265). There is no alternative in the mobile drawer (`rtbit-web.tsx:254-265` renders only `<Sidebar />`).
- **Category:** Responsive.
- **Evidence:** compare `01-torrents-mobile-*.png` (no nav) with `01-torrents-desktop-*.png`. Navigating to RSS failed in the Playwright run at 390 px.
- **Impact:** phone and narrow-window users can't manage RSS feeds or rules at all. The narrow window case includes a resized desktop app.
- **Recommendation:** add the page links to the top of the mobile drawer, or as a bottom/segmented nav when `!isLargeScreen`.
- **Command:** `/impeccable adapt`.

**P0-2. Torrent table rows can't be used from the keyboard**
- **Location:** `components/compact/TorrentTableRow.tsx:401-403`. This is a `<tr onMouseDown={handleRowClick} onContextMenu=...>` with no `tabIndex`, `role` or `onKeyDown`. `components/compact/TorrentTable.tsx` has no keyboard handling either.
- **Category:** Accessibility.
- **Evidence:** `09-focus-desktop-light.png`. After six Tabs, focus lands on toolbar icons and never enters the list.
- **Impact:** keyboard-only users can't select, open details for, or act on a torrent.
- **Standard:** WCAG 2.1.1 Keyboard (A).
- **Recommendation:** use the grid pattern: `role="grid"`, a roving `tabIndex` on rows, Up/Down to move, Space to toggle selection, Enter to open details, and Shift+F10 or the ContextMenu key to open the menu.
- **Command:** `/impeccable harden`.

**P0-3. Icon-only controls have no accessible name**
- **Location:**
  - `components/Toolbar.tsx:284-289` (search clear, `<GoX/>` only).
  - `components/compact/ActionBar.tsx:243-248` (search clear).
  - `components/buttons/TorrentActions.tsx:78-93` (play, pause, configure and delete `IconButton`s with no `title` or label).
  - The toolbar icons at `components/Toolbar.tsx:316-391` rely on `title` only.
- **Category:** Accessibility.
- **Evidence:** the DOM probe found 8 unnamed buttons on the main view. In the whole tree, `aria-label` appears only once (`components/modal/Modal.tsx:25`).
- **Impact:** a screen reader announces "button" or "link" with no purpose. `title` is not exposed on touch.
- **Standard:** WCAG 4.1.2 Name, Role, Value (A).
- **Recommendation:** give every icon-only control an `aria-label` and keep `title` as the tooltip.
- **Command:** `/impeccable harden`.

**P0-4. `IconButton` is a link pretending to be a button**
- **Location:** `components/buttons/IconButton.tsx:32-38`. It renders `<a ... href={href ?? "#"} onClick={...preventDefault}>`.
- **Category:** Accessibility.
- **Impact:** it is announced as a link, Space doesn't activate it, and in its "disabled" state it stays focusable and is announced as enabled. Every card-view action (`TorrentActions`) uses it.
- **Standard:** WCAG 4.1.2 (A).
- **Recommendation:** render `<button type="button" disabled={disabled} aria-label=...>`.
- **Command:** `/impeccable harden`.

### P1 — Major

**P1-1. Focus indicators are removed on about 20 inputs**
- **Location:** these inputs use `focus:outline-none focus:border-primary` (only a 1 px border colour change):
  - `components/Toolbar.tsx:281`
  - `components/compact/ActionBar.tsx:220,240`
  - `components/CardLayout.tsx:128,144,159`
  - `components/auth/LoginPage.tsx:29`
  - `components/auth/SetupPage.tsx:41`
  - `components/RSSPage.tsx:94,280,526`
  - `components/TorrentContextMenu.tsx:379`
  - `components/config/SecurityTab.tsx:59`
- **Category:** Accessibility.
- **Note:** the toolbar icon buttons do show a ring (`09-focus-desktop-light.png`), so the problem is the inputs.
- **Standard:** WCAG 2.4.7 Focus Visible (AA), 1.4.11 Non-text Contrast.
- **Recommendation:** add one shared `focus-visible:ring-2 ring-primary/50` utility in `globals.css`.

**P1-2. Search, filter and sort controls have no label**
- **Location:**
  - Placeholder used as the only label: `components/Toolbar.tsx:280` (`Filter...`), `components/compact/ActionBar.tsx:239` and `components/CardLayout.tsx:127` (`Search...`).
  - Unlabelled `<select>`s: `components/CardLayout.tsx:144,159` (the "All" and "ID ↓" selects in `01-torrents-mobile-*.png`) and `components/compact/ActionBar.tsx:220`.
- **Standard:** WCAG 1.3.1, 3.3.2 (A).
- **Recommendation:** add an `aria-label`, or a visually hidden `<label>`.

**P1-3. The tertiary text token fails contrast in both themes**
- **Location:** `globals.css:21` (`--color-tertiary: slate-400`) on `--color-surface: white` (`globals.css:14`) is about 2.6:1. The dark value (slate-500 on slate-900) is about 3.9:1.
- **Usage:** 85 sites, including the sidebar section headings (`components/Sidebar.tsx:141`, `compact/CategoryFilter.tsx:98`, `compact/TrackerFilter.tsx:75`), the table IDs, the "Collapse" control and the footer secondary values.
- **Evidence:** `01-torrents-desktop-light.png` (STATUS, CATEGORIES and TRACKERS headings, the ID column and the "Paused" pills).
- **Standard:** WCAG 1.4.3 (AA).
- **Recommendation:** light slate-500 (about 4.8:1), dark slate-400 (about 6:1).

**P1-4. Sort headers can't be focused and don't announce their state**
- **Location:** `components/compact/TorrentTable.tsx:450-456` and `components/compact/PeersTab.tsx:220` use `<th onClick=...>`.
- **Standard:** WCAG 2.1.1, 4.1.2.
- **Recommendation:** put a `<button>` inside each `<th>` and set `aria-sort` on the `<th>`.

**P1-5. Column resize works only with a mouse and has a 6 px hit area**
- **Location:** `components/compact/TorrentTable.tsx:466-468` (`w-1.5 cursor-col-resize onMouseDown`).
- **Category:** Responsive/A11y.
- **Recommendation:** use pointer events with `setPointerCapture` and `touch-action: none`, a hit area of at least 12 px, and `role="separator"` with arrow-key resizing.

**P1-6. Context-menu actions can't be reached without a right-click**
- **Location:** `components/compact/TorrentTableRow.tsx:403`, `components/compact/TorrentTable.tsx:369,410` and `components/CardLayout.tsx:99`. Only `onContextMenu` opens the menu, and there is no long-press or "…" button.
- **Impact:** on touch (cards at 390 px), Force Recheck, Sequential Download, Speed/Seed Limits, Set Category and the Copy Name/Hash/Magnet actions can't be reached. The menu is shown in `03-contextmenu-desktop-*.png`.
- **Recommendation:** add a "⋯" button to each card and row that opens the same `TorrentContextMenu` anchored to the button. Add long-press as a bonus.
- **Command:** `/impeccable adapt`.

**P1-7. The context menu has no menu semantics and doesn't manage focus**
- **Location:** `components/TorrentContextMenu.tsx:400-470`. The items are plain `<button>`s: no `role="menu"`/`menuitem`, no arrow keys, and focus isn't moved into the menu or restored afterwards. Escape does close it (line 133).
- **Standard:** WCAG 4.1.2, ARIA APG Menu.

**P1-8. The context menu goes off-screen on short viewports**
- **Location:** `components/TorrentContextMenu.tsx:147-150` (`top = Math.min(y, window.innerHeight - 500 - 8)`).
- **Failure:** when `innerHeight` is below 508 (a phone in landscape, or a small desktop window), `top` is negative and the first items are clipped.
- **Recommendation:** use `Math.max(8, …)`, measure the real height after mount, and add `max-h-[calc(100vh-16px)] overflow-y-auto`.

**P1-9. The mobile toolbar add buttons wrap to four lines**
- **Location:** the labels are hard-coded at `components/buttons/MagnetInput.tsx:37` ("Add Torrent from Magnet / URL") and `components/buttons/FileInput.tsx:89` ("Upload .torrent File"). They render in `components/Toolbar.tsx` with no compact variant.
- **Evidence:** in `01-torrents-mobile-light.png` and `01-torrents-mobile-dark.png`, the toolbar is about 105 px tall and the buttons are four-line stacks.
- **Recommendation:** below `sm`, show icon plus short label ("Magnet", "Upload"), or a single "+ Add" button that opens a menu.

**P1-10. Touch targets are well under 44 px**
- **Measurements:**
  - Toolbar icons are about 28 px (`components/Toolbar.tsx:200-201`, `p-1.5` around `w-4 h-4`).
  - Search clear buttons are about 18 px (`Toolbar.tsx:286`, `ActionBar.tsx:245`).
  - `IconButton` uses `p-1`.
  - Table rows are 32 px (`TorrentTableRow.tsx:404`).
  - The card action icons (play/cog/trash in `01-torrents-mobile-*.png`) are about 16 px.
- **Count:** 31 small targets at 390 px.
- **Standard:** WCAG 2.5.8 Target Size (AA, 24 px minimum); 44 px is the platform guideline.
- **Recommendation:** add `@media (pointer: coarse)` padding to the shared button primitives.

**P1-11. The mobile settings tabs are clipped with no visible scroll**
- **Location:** `components/Tabs.tsx:33` (`flex border-b` with no overflow handling), used by `components/modal/TabbedConfigModal.tsx`.
- **Evidence:** in `05-settings-mobile-light.png`, "Queue…" is cut off at the edge, and tabs from Seeding onward are invisible.
- **Recommendation:** use `overflow-x-auto` with `scroll-snap`, add an edge fade, and scroll the active tab into view. Alternatively, switch to a `<select>` below `sm`.

**P1-12. The "no daemon" and API error state is a raw HTTP string**
- **Location:** `rtbit-web.tsx:81` (`setOtherError({ text: "Error refreshing torrents", details: e })`), rendered by `components/ErrorComponent.tsx:12`.
- **Evidence:** `10-no-daemon-*.png` shows "Error refreshing torrents / 404 Not Found" over an empty list with live-looking filter controls. It doesn't explain what is wrong, doesn't say a retry is in progress, and has no Retry button.
- **Recommendation:** show a dedicated "Can't reach the rustTorrent engine" state with the API URL, an automatic-retry indicator and a Retry button, and hide the list chrome while it shows.
- **Command:** `/impeccable harden`, `/impeccable clarify`.

**P1-13. Polling never pauses in hidden tabs or a minimised desktop app**
- **Location:** there are no `document.hidden`/`visibilitychange` checks. The polling sites are:
  - `rtbit-web.tsx:97` (torrents) and `rtbit-web.tsx:101-113` (stats every 1 s)
  - `compact/SpeedTab.tsx:38` (1 s)
  - `compact/PeersTab.tsx:70`
  - `compact/PiecesCanvas.tsx:28`
  - `Footer.tsx:51`
  - `RSSPage.tsx:440`
  - `IndexarrBrowse.tsx:149`
  - `main.tsx:97`
- **Category:** Performance.
- **Recommendation:** make `helper/customSetInterval.ts` back off, or pause, while `document.hidden` is true and refresh immediately on `visibilitychange`.

### P2 — Minor

1. **The detail pane fetches stats twice.** `compact/SpeedTab.tsx:38-58` polls `getTorrentStats` every second, while the store loop already refreshes stats (`rtbit-web.tsx:97`). Derive the speed history from the store instead. *(Performance)*
2. **The polling effect has a stale closure.** `rtbit-web.tsx:92-98` sets the refresher once with `[]` deps and an `as unknown as () => void` cast, which hides the type mismatch and captures the first render's `API`. *(Integrity)*
3. **There is no code-splitting.** No `lazy(` or dynamic `import(` exists. `RSSPage.tsx` (824 lines), `IndexarrBrowse.tsx` (655), `LogStream.tsx` (350), the config tabs and the SpeedTab chart all ship in the main bundle. *(Performance)*
4. **Each card gets a new closure on every render.** `CardLayout.tsx:91-108` creates an inline `onContextMenu` per item. *(Performance)*
5. **Dynamic Tailwind class names never apply.** `buttons/IconButton.tsx:30` builds `` `text-${color}` ``, which Tailwind can't detect at build time, so the colour is never applied. *(Integrity)*
6. **A blue accent leaks into the orange brand.** This shows on the card actions in `01-torrents-mobile-*.png`. It also affects the desktop table progress bars, which are blue while the card bars are orange: compare `01-torrents-desktop-light.png` with the mobile capture. The sources are:
   - `buttons/IconButton.tsx:33` (`text-blue-500`)
   - `buttons/MagnetInput.tsx:36` and `buttons/FileInput.tsx:88`
   - `forms/FormCheckbox.tsx:43`
   - `modal/DeleteTorrentModal.tsx:105`
   *(Theming)*
7. **Hover-only action colour.** `buttons/TorrentActions.tsx:79,84,89,93` set `hover:text-green-600` on play and also on the configure cog, so the meaning shows only on hover, and configure looks like play. *(Theming/Responsive)*
8. **Brand orange is used for data values.** `config/GeneralTab.tsx:9,45`, `config/DHTTab.tsx:9` and `config/ConnectionTab.tsx:9,27,28` apply `text-primary` to plain stats such as Version and Uptime (`05-settings-mobile-light.png`), so every value reads as a link or action. Use `text-text` with `font-medium tabular-nums`. *(Theming)*
9. **Raw palette colours bypass the status tokens.** These should use the `text-success`/`text-error`/`*-bg` tokens. Gray is also mixed with slate. The sites are:
   - `RSSPage.tsx:107,293,606,684-685,765-766`
   - `config/SecurityTab.tsx:83`
   - `modal/MultiTorrentUploadModal.tsx:93,95,155`
   - `IndexarrSetup.tsx:166`
   - `IndexarrBrowse.tsx:566,631`
   - `LogStream.tsx:56-62`
   - `modal/DeleteTorrentModal.tsx:82`
   *(Theming)*
10. **The speed chart hard-codes hex colours.** `compact/SpeedTab.tsx:121,126` uses `#60a5fa/#2563eb` and `#34d399/#059669`, duplicating `--color-accent-download`/`--color-accent-upload` (`globals.css:39-40`). Read the CSS variables as `compact/PiecesCanvas.tsx:66` already does. *(Theming)*
11. **The Indexarr badges have no light-mode variant.** `IndexarrBrowse.tsx:47-51` uses `text-yellow-400` and `text-blue-400`. On white, the yellow is about 1.5:1. *(Theming/A11y)*
12. **The progress bar label breaks at low values.** `ProgressBar.tsx:20-27` centres the label inside the filled segment. Two things go wrong:
    - At under about 8%, the label overflows onto the track. In `01-torrents-mobile-light.png`, "0.43%" sits on grey, and white text on a light track would be invisible. Below 1% the fill becomes `bg-transparent`, so the white label sits on the light track.
    - `now < 1 && "bg-transparent"` puts the literal class `false` into `className`.
    Render the label outside or over the full track with a contrasting colour. *(A11y/Integrity)*
13. **The mobile drawer is narrower than its container.** In `rtbit-web.tsx:261`, the wrapper is `w-64` but `components/Sidebar.tsx:137` is `w-48`, and the sidebar doesn't fill the height. `08-sidebar-mobile-light.png` shows a 2-tone strip and white space below "Collapse".     *(Theming/Integrity)*
22. **The splash status isn't announced, and the spinner ignores reduced motion.** `desktop/src/index.html:45-46` has no `role="status"`, and the spinner has no `prefers-reduced-motion` alternative. *(A11y)*
23. **The splash never fails.** `desktop/src/index.html:49-57` runs `while (true)` polling every 200 ms with no timeout or error message. If the engine fails to bind, the user waits forever. *(Harden)*

### P3 — Polish

2. **The input class string is copy-pasted about 19 times.** See `TorrentContextMenu.tsx:378`, `config/RSSTab.tsx:29` and `RSSPage.tsx:93,279`. Create a shared `TextInput` component or `@utility`.
3. **There are four button systems.** `Toolbar.tsx:200-203` (`toolbarIcon*`), `RSSPage.tsx:494` (`btnSmCls`), `buttons/Button.tsx` and `buttons/IconButton.tsx`.
4. **Corner radii drift.** There are 103 `rounded`, 21 `rounded-lg`, 2 `rounded-md` and 1 `rounded-xl`. The same search field is `rounded-lg` in `Toolbar.tsx:281` but `rounded` in `ActionBar.tsx:240`.
5. **Copy is inconsistent.**
   - The search placeholder is "Filter..." (`Toolbar.tsx:280`) but "Search..." (`ActionBar.tsx:239`, `CardLayout.tsx:127`).
   - The toolbar titles mix "Logout", "View logs" and "Configure".
   - Labels mix "Add torrent" (modal title) and "Add Torrent from Magnet / URL" (button).
6. **There is dead code.** `config/AdvancedTab.tsx` and `compact/TableHeader.tsx` are never imported.
7. **Clear buttons have no explicit type.** The search clear buttons (`Toolbar.tsx:284`, `ActionBar.tsx:243`) default to `type="submit"`.
8. **The empty detail pane wastes space.** At 1440 px the detail pane takes about 30% of the height to say "Select a torrent to view details" (`01-torrents-desktop-light.png`). Collapse it to a thin bar until something is selected.

## Patterns and systemic issues

- **Accessible naming is close to absent.** The app has one `aria-label` in total, every icon control relies on `title`, and the core list is mouse-only. This is a single systemic gap: fixing the primitives (`IconButton`, toolbar icon class, the row) fixes most of it.
- **Breakpoint gating removes features rather than adapting them.** `isLargeScreen` hides the page nav, the search box (`hidden lg:block`) and the column UI, and nothing replaces them on mobile.
- **Blue accent leakage.** Seven files use `text-blue-*` for interactive affordances, against an orange `--color-primary`.
- **Feature pages bypass the tokens.** RSS, Indexarr, logs and some modals use the raw Tailwind palette, while core views use tokens.
- **Controls are duplicated.** There are four button systems, about 19 input class strings and two progress-bar colour paths.

## Positive findings

- `globals.css` has a clean semantic token layer (surface, text, divider, primary, status and download/upload accents) with a complete `.dark` override. Most components use it, and the dark theme renders cleanly (`02-detail-desktop-dark.png`, `04-rss-desktop-dark.png`).
- `modal/Modal.tsx` sits on `@restart/ui`, which provides the focus trap, Escape, focus restore and the dialog role.
- Lists are virtualised (`react-virtuoso`) and rows are memoised (`TorrentTableRow.tsx:417`). About 30 `memo`/`useMemo` sites exist.
- `customSetInterval` already supports adaptive back-off after errors. `PiecesCanvas` reads its colours from CSS variables.
- Keyboard shortcuts (`hooks/useKeyboardShortcuts.ts`) are suppressed while dialogs are open. The toolbar icon buttons show a visible focus ring.
- The dense desktop table reads well: numbers align, status pills are tidy, and the error row ("Connection timed out") is placed well.
- There is no page-level horizontal overflow at 390 px.

## Recommended actions

1. **[P0] `/impeccable adapt`:** add mobile page navigation and a touch path to the context menu (P0-1, P1-6, P1-9, P1-11, P2-13).
2. **[P0] `/impeccable harden`:** keyboard grid, real buttons, accessible names, menu semantics (P0-2, P0-3, P0-4, P1-4, P1-7).
3. **[P1] `/impeccable colorize` / tokens:** fix the tertiary contrast, remove the blue leak, and move feature pages onto the tokens (P1-3, P2-6 to P2-11).
4. **[P1] `/impeccable harden` + `/impeccable clarify`:** an engine-unreachable state in the web UI and the desktop splash (P1-12, P2-21 to P2-23).
5. **[P1] `/impeccable optimize`:** visibility-aware polling, dedupe SpeedTab, lazy-load feature pages (P1-13, P2-1 to P2-4).
6. **[P3] `/impeccable polish`:** consolidate the primitives, copy and radii, and remove the dead code.
