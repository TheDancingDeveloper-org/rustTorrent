# rustTorrent v0.2.0-beta.1

## Summary

rustTorrent 0.2.0-beta.1 turns the Web UI into something usable without a mouse
and substantially widens the WebUI API v2 compatibility layer. It adds
persistent sessions, revocable API keys, a read-only role, native torrent tags,
queue ordering with force-start, per-torrent speed limits, and live move and
rename of running torrents.

It also reworks persistence so queue, disk and share-limit state survives a
restart, adds an on-complete command and webhook, and rounds out packaging with
RPM packages, signed Windows binaries, an SBOM and channel manifests.

This remains beta software. Back up the persistent session directory and the
PostgreSQL database before upgrading, and avoid using it for data that cannot
be downloaded again.

## What changed since 0.1.0-rc.1

- **Web UI API v2 compat** grew from 66 to 81 of 97 in-scope endpoints, 36 of
  them full, across `auth`, `app`, `torrents`, `transfer`, `sync`,
  `torrentcreator`, `clientdata` and `log`. `transfer` and `log` are now fully
  routed.
- **Authentication** is persisted across restarts, gains revocable API keys and
  a read-only role, and first-run setup is protected by a one-time setup token.
- **The engine** gains an on-complete hook, active-download and active-seed
  limits, a minimum free-disk guard, `.part` handling, and full live move and
  rename of running torrents.
- **The desktop app** opens `.torrent` files and magnet links from the OS,
  forwards them to a single running instance, and adds a tray icon, autostart,
  an updater and a themed splash screen.
- **The web UI** is keyboard and screen-reader accessible throughout: a roving
  tabindex torrent table, `aria-sort` headers, context menus on `Shift+F10`,
  44 px rows on coarse pointers, a mobile navigation drawer, and WCAG AA status
  colours in both themes.
- **Packaging** adds RPM packages, Authenticode-signed Windows executables, a
  CycloneDX SBOM, and AUR, Homebrew, Flatpak and winget manifests rendered per
  release.

## Upgrade notes

- Back up `/home/rtbit/db`, `/home/rtbit/cache` and the credentials directory
  (which now also holds `sessions.json` and `api_keys.json`) before upgrading.
- **First-run setup now requires a setup token.** It is printed in the daemon
  log and written to an owner-only `setup-token` file while setup is pending.
  Scripted provisioning that posts to the setup endpoint must pass it. The
  token is single-use and is not consumed by the CLI.
- **Existing passwords are migrated automatically.** A plaintext
  `credentials.json` is rewritten with an argon2 hash on first start. Changing
  the admin password or read-only account signs out every existing session,
  and logins are capped at 30 days.
- **The PostgreSQL schema gains columns.** Queue, disk-hold and share-limit
  state, the have-bitfield, output-folder roots, file renames and the
  uploaded byte total are added with `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`
  at startup. This is additive and non-destructive, but back up the database
  first. Older binaries ignore the new columns when downgrading.
- **Tag storage moved** from `qbit-tags.json` to `tags.json` plus per-torrent
  state. The legacy file is imported once at startup and left in place.
- **Log files are less verbose by default.** `--log-file` now uses the `info`
  filter instead of `librtbit=debug,info`. Pass an explicit filter to restore
  the old detail, and use `--log-format json` for structured logs.
- **`app/version` now reports `v5.0.0`** (was `v0.0.1`), because *arr apps gate
  features on it. The advertised `webapiVersion` is unchanged at `2.11.3`.
- **macOS is no longer a desktop bundle target.** Linux and Windows are
  supported. The self-updater is a `self-update` feature and is disabled in the
  Flatpak build.
- For migrations from another client, use `--storage-read-only` for the first
  verification pass and confirm the payload root expected by each imported
  torrent. That behaviour is unchanged from 0.1.0-rc.1.
- `latest` and `beta` move to this release after publication. Pin
  `v0.2.0-beta.1` when reproducibility matters.

## Added

- Persistent sessions (hashed at rest and bound to the credential that issued
  them) and revocable API keys (`Bearer rtb_...`) through `GET`/`POST
  `/auth/api_keys` and `DELETE /auth/api_keys/{id}`, plus a read-only role.
- A one-time first-run setup token and argon2 password hashing, with automatic
  migration of a plaintext `credentials.json`.
- An optional TOML config file (`--config` or `RTBIT_CONFIG`) for non-secret
  settings, with `CLI > environment > file > default` precedence, unknown keys
  rejected, and `rtbit config dump`.
- An on-complete shell command and JSON webhook with `RTBIT_EVENT`,
  `RTBIT_TORRENT_ID`, `RTBIT_INFO_HASH`, `RTBIT_TORRENT_NAME`,
  `RTBIT_OUTPUT_FOLDER` and `RTBIT_COMPLETED_AT`. It does not fire for torrents
  that were already complete when the session was restored.
- Active-download and active-seed limits, a minimum free-disk guard, and
  `.part` handling for in-progress payloads.
- `--log-file-rotation never|hourly|daily`, `--log-file-max-files N` and
  `--log-format text|json`.
- An unauthenticated `/healthz` route, a Docker `HEALTHCHECK`, hardened systemd
  units, and a per-user unit that runs `rtbit` by name.
- A startup banner reporting the Web UI URL, auth state, folders and listen
  address, and Indexarr flags (`--indexarr-enabled`, `--indexarr-url`,
  `--indexarr-api-key`, plus `RTBIT_INDEXARR_*`).
- Desktop OS integration: open `.torrent` and magnet links, single-instance
  forwarding, Linux `%U` handling, tray, autostart, updater and a themed splash
  screen with a failure state and retry.
- Web UI accessibility: design tokens and primitives, a mobile navigation
  drawer, an "engine unreachable" panel with retry, labelled toolbar and search
  controls, an `aria-pressed` theme toggle, a roving-tabindex torrent table
  with `Shift+F10`/context menus, `aria-sort` headers, keyboard column
  resizing, and 44 px rows on coarse pointers.
- Web UI features: settings search, restart markers, queue empty state and
  expiry notice, paste and drag-and-drop adding, toasts, a connection-lost
  banner, a keyboard shortcuts overlay with view preferences, and consistent
  feature-page theming.
- WebUI API v2 compat: full torrent-creator task options (private, comment,
  URL seeds, `torrentFilePath`, `startSeeding`, v2 and hybrid formats).
- WebUI API v2 compat: sequential download and first/last piece priority
  (`toggleSequentialDownload`, `toggleFirstLastPiecePrio`, `seq_dl`,
  `f_l_piece_prio`), honoured by `picker`.
- WebUI API v2 compat: `log/main` and `log/peers` over a bounded log ring, and
  session peer bans through `transfer/banPeers`.
- WebUI API v2 compat: live move and rename of running torrents (`setLocation`,
  `setSavePath`, `renameFile`, `renameFolder`), persisted across reloads.
- WebUI API v2 compat: `clientdata/load` and `clientdata/store`, and
  `comment`, `created_by` and `creation_date` in `torrents/properties`.
- WebUI API v2 compat: live tracker add, edit and remove, with forced
  reannounce.
- Native torrent tags: a session tag registry and per-torrent tag set persisted
  in `tags.json` and per-torrent state, used by the compat tag endpoints, the
  `torrents/info` `tags` field and `tag` filter, and `torrents/add`.
- Torrent queue ordering and force-start: a persisted queue position followed
  by the policy pass, force-started torrents outside the limits, and
  `topPrio`/`bottomPrio`/`increasePrio`/`decreasePrio`, `setForceStart`, the
  `queuedDL`/`queuedUP`/`forcedDL`/`forcedUP` states, and queueing preferences.
- Per-torrent speed limits saved across restarts, a native
  `GET`/`POST /torrents/{id}/limits`, and `dl_limit`/`up_limit` reporting.
- Session speed limits through `transfer/getSpeedLimits` and
  `transfer/setSpeedLimits`, and real `dht_nodes` in `transfer/info` and
  `sync/maindata`.
- A `sync/maindata` rid delta protocol (changed fields plus `*_removed` lists)
  and `sync/torrentPeers` with the same rid encoding.
- WebUI API v2 compat conformance tests: a response contract for every routed
  endpoint in `qbit_parity_spec.json`, validated against a live torrent, plus
  an add/stop/start/recheck/setCategory/delete lifecycle test.
- RPM packages alongside the Debian package, a CycloneDX SBOM, and
  Authenticode signing of the Windows executable with an RFC 3161 timestamp,
  verified by `verify-release.sh`.
- AUR (`rtbit-bin`), Homebrew, Flatpak (offline, with a signed vendor tarball)
  and winget manifests rendered per release, failing closed when a digest or
  placeholder is missing.
- Keyless cosign verification of `SHA256SUMS` and every listed artefact before
  a release is published.

## Changed

- WebUI API v2 compat coverage grew from 66 to 81 of 97 in-scope endpoints (36
  full, 45 partial). `transfer` and `log` are now fully routed.
- `app/version` reports `v5.0.0`; `webapiVersion` remains `2.11.3`.
- Torrent tags moved from `qbit-tags.json` to `tags.json` plus per-torrent
  state, with a one-time import of the legacy file.
- `--log-file` defaults to the `info` filter instead of
  `librtbit=debug,info`.
- The compat layer is split into per-controller modules; this is
  behaviour-neutral and internal.
- Web UI polling is visibility-aware, the speed tab reads from the session
  store, and feature pages load lazily.
- The desktop app targets Linux and Windows only; macOS bundle targets were
  removed and the self-updater moved behind the `self-update` feature.
- The `torrents` table gains additive columns for queue and share state,
  `.part` handling, output-folder roots, file renames and the have-bitfield.

## Fixed

- `torrentcreator/status` emits `taskID` (was `taskId`), matching upstream.
- `setPreferences` applies speed and seeding limits partially, ignores unknown
  fields, and accepts a missing `announce_port` instead of rejecting the
  request.
- Session IDs expire after one hour of inactivity and idle sessions are
  purged.
- Torrents that were queued, held for disk space or paused by a share limit no
  longer come back permanently paused after a restart.
- Share limits, the uploaded byte total and the `.part` choice persist
  correctly. State is also saved on a 60 s timer and at shutdown.
- PostgreSQL persistence no longer binds a parameter twice, and writes are
  serialised behind a single lock.
- A hanging on-complete command is bounded by a timeout, and resuming a
  torrent resets the share-limit inactivity clock.
- Desktop reads hashed credentials correctly, read-only accounts can log out,
  and the CLI no longer consumes the pending setup token.
- The `M` shortcut reopens the shortcuts overlay reliably, focus follows
  Home/End scrolling, and the overflow menu is named "More options" and
  keyboard operable.
- Status text meets WCAG AA contrast in both themes.
- An invalid CORS allow regexp is logged as a warning; `RTBIT_CORS_ALLOW_REGEXP`
  takes precedence over the bare `CORS_ALLOW_REGEXP`.
- Tests no longer write compat tags into the user's real data directory.
